# Jev Router + Hermes Agent — расчёты, настройка и оптимальное совмещение

## О чём этот документ

Этот документ описывает, как использовать Jev Router (typesafe/jev-router) совместно с Hermes Agent через OpenRouter, какие расходы это влечёт при активной работе, как настроить пулы моделей и как правильно совместить Jev Router со встроенным роутером провайдеров Hermes.

Документ предназначен для пользователей, которые уже знакомы с базовой настройкой Hermes Agent и хотят оптимизировать расходы на LLM при интенсивной работе.


## 1. Расчёт стоимости: сколько это стоит в месяц

### 1.1. Схема работы

При использовании Jev Router через OpenRouter с Hermes Agent работает следующая цепочка:

1. Вы даёте Hermes Agent ключ OpenRouter (OPENROUTER_API_KEY).
2. Выбираете модель `typesafe/jev-router` в качестве основной модели сессии.
3. Пишете запросы в Hermes.
4. Jev Router анализирует каждый запрос и выбирает оптимальную модель из доступного пула.
5. Выбранная модель генерирует ответ, который возвращается в Hermes.

Плагин не требуется — достаточно указать модель `typesafe/jev-router` в настройках Hermes или в запросе к OpenRouter.

### 1.2. Из чего складываются расходы

Расходы состоят из трёх компонентов:

**Компонент 1: Решения Jev.** Jev — это не языковая модель, а решатель (System One). Он читает состояние и вопросы, возвращает типизированные ответы. Тарификация: **$0.042 за 1M входных токенов**, выходные токены **бесплатны**. Замеры на реальных сценариях показывают, что одно решение стоит **$0.0000153–$0.0000226** — примерно в 20 раз меньше распространённой оценки в $0.0004. При 30 000 решений в месяц расходы на Jev составят около **$0.5–$0.7**.

**Компонент 2: Генерация ответов моделями.** Это основная статья расходов. Jev Router направляет запросы к разным моделям в зависимости от сложности задачи. Цена за 1M токенов у этих моделей различается на порядки.

**Компонент 3: Комиссия OpenRouter.** При пополнении баланса взимается комиссия **5.5%** (на тарифе Standard).

### 1.3. Оценка при активной работе (6 часов в день)

Возьмём ваши условия: **6 часов активной работы в день** (около 180 часов в месяц). Предположим, что в активном режиме Hermes Agent совершает **10–30 запросов в час** (среднее — 20).

**Расчёт количества запросов:**
6 часов × 30 дней × 20 запросов/час = **3 600 запросов в месяц**.

**Стоимость генерации (при распределении 50% лёгких / 40% средних / 10% сложных и среднем запросе ~2 000 входных + 500 выходных токенов):**

| Уровень | Модель-пример | Цена (вход/выход за 1M) | Стоимость запроса |
| :--- | :--- | :--- | :--- |
| Лёгкий | DeepSeek V4 Flash | $0.03 / $1.28 | ~$0.0007 |
| Средний | GPT-6 Sol | $2.00 / $10.00 | ~$0.009 |
| Сложный | GPT-6 Astra | $4.00 / $20.00 | ~$0.018 |

Средняя стоимость запроса: (0.5 × $0.0007) + (0.4 × $0.009) + (0.1 × $0.018) = **$0.00575**.

**Итого за генерацию:** 3 600 × $0.00575 ≈ **$20.70**.

**Итого за Jev:** ~**$0.5–$0.7**.

**Комиссия OpenRouter (5.5%):** ~**$1.2**.

**Общая оценка: ~$22–$25 в месяц** при указанных допущениях. Эта цифра сильно зависит от реальной интенсивности работы, сложности задач и выбранных моделей.

> **Важно:** Jev почти не завышает сложность — в тестах на 120 контрольных сообщениях ошибок «сложное → лёгкая модель» было **0**. Это означает, что дорогие модели не будут вызываться там, где в них нет необходимости.


## 2. Встроенный роутер Hermes: что это и зачем он нужен

Встроенный роутер — это не «выбиральщик моделей» под задачу, а **инфраструктурный слой** управления провайдерами.

### 2.1. Центральный роутер (v0.2.0)

Все вызовы LLM в Hermes проходят через единую функцию `call_llm()` — чат, зрение, суммаризация, сжатие контекста, сохранение траекторий. Это устраняет ситуацию, когда разные части агента обращаются к LLM по-разному и используют разные учётные данные.

### 2.2. Цепочка fallback-провайдеров (v0.6.0)

Вы указываете в `config.yaml` список провайдеров по порядку. Если основной провайдер возвращает ошибку (429 — лимит, 500 — сбой, недоступный эндпоинт), Hermes автоматически переключается на следующего в списке. Цепочка **упорядоченная**, а не round-robin: вы выбираете приоритет и резерв.

Пример настройки в `~/.hermes/config.yaml`:
```yaml
fallback_providers:
  - provider: openrouter
    model: anthropic/claude-sonnet-4
  - provider: anthropic
    model: claude-sonnet-4
  - provider: nous
    model: hermes-3
```

### 2.3. Пулы учётных данных (v0.7.0)

Один провайдер может иметь несколько API-ключей (личный, командный, резервный). Hermes использует наименее загруженный ключ и автоматически ротирует его при ошибке 401.

### 2.4. Ключевое ограничение

Встроенный роутер **не выбирает модель под задачу**. Он выбирает **провайдера** для уже выбранной модели (или основной модели сессии), исходя из доступности, а не из сложности запроса. Это его фундаментальное отличие от Jev Router.


## 3. Jev Router: интеллектуальный слой для экономии

### 3.1. Что делает Jev Router

Jev Router (`typesafe/jev-router`) — это OpenRouter-роутер, который на каждом запросе:

1. Читает разговор.
2. Оценивает тип задачи, сложность и то, насколько сильная модель поможет.
3. Выбирает **самую дешёвую модель**, которая соответствует этому уровню, из вашего пула.

Jev **не пишет текст**. Он отвечает на узкие вопросы о сообщении за ~270–500 мс и возвращает типизированное решение.

### 3.2. Точность

Проверено на 241 реальном сообщении (из работы, кода, учёбы, контента). Контрольные 120 сообщений писал отдельный автор, правило решения зафиксировано до проверки.

| Метрика | Jev Router | Простой роутер |
| :--- | :--- | :--- |
| Точность | **95.8–97.5%** | 65% |
| Занизил уровень | 0–1 из 120 | 24 из 120 |
| Из них «сложное → лёгкая» | **0** | 0 |
| Завысил уровень | 3–4 из 120 | 18 из 120 |

Почти все ошибки — в безопасную сторону: лёгкое задание уходит в среднюю модель.

### 3.3. Стоимость решений Jev

Jev тарифицируется по **$0.042 за 1M входных токенов**. Выходные токены бесплатны. Реальное решение на типичном запросе стоит **$0.0000153–$0.0000226**. При 3 600 запросах в месяц это **меньше $0.1**.

### 3.4. Настройка пула моделей

**Способ 1: Через параметры плагина в запросе (разово)**

Вы передаёте объект `plugins` в теле API-запроса:

```json
{
  "model": "typesafe/jev-router",
  "plugins": [
    {
      "id": "jev-router",
      "models": ["anthropic/*", "google/*"],
      "excluded_models": ["anthropic/claude-opus*"]
    }
  ],
  "messages": [
    {"role": "user", "content": "Суммаризируй отчёт."}
  ]
}
```

- `models` — список-включатель. Jev выбирает **только** из этого списка.
- `excluded_models` — список-исключатель. Имеет приоритет над `models`.
- Поддерживаются: точные ID (`openai/gpt-6-luna`), шаблоны (`anthropic/*`), псевдонимы (`~openai/gpt-luna-latest`).
- **Важно:** эти списки только **сужают** пул, из которого Jev выбирает. Они не добавляют новые модели.

**Способ 2: Через файл конфигурации (постоянно)**

Файл `routing.json` задаёт пулы моделей по умолчанию:

```json
{
  "tiers": {
    "simple": {
      "general": ["openrouter:deepseek/deepseek-v4.1-flash"]
    },
    "medium": {
      "general": ["openrouter:openai/gpt-6-sol"],
      "coding": ["openrouter:openai/gpt-6-sol"]
    },
    "hard": {
      "general": ["openrouter:openai/gpt-6-astra"],
      "coding": ["openrouter:openai/gpt-6-astra"]
    }
  },
  "exclude": ["*:free"]
}
```

Пути к файлу:
- `~/.hermes/jev/routing.json` — для всех профилей.
- `~/.hermes/profiles/<имя>/jev/routing.json` — для конкретного профиля.

Jev выбирает **первую подходящую** модель из списка, поэтому размещайте предпочтительные и более дешёвые модели в начале.

**Способ 3: Автоматическая генерация черновика**

Команда `jev models suggest --write` анализирует каталог моделей, группирует их по ценовым категориям и записывает черновой `routing.json`. Полученный файл нужно доработать вручную.


## 4. Как совместить встроенный роутер Hermes и Jev Router

Встроенный роутер и Jev Router **не заменяют, а дополняют** друг друга. Встроенный роутер обеспечивает **надёжность** (переключение провайдеров при сбоях), Jev Router — **экономию** (выбор модели под задачу).

### 4.1. Рекомендуемая архитектура

```
Запрос пользователя
       │
       ▼
Jev Router (typesafe/jev-router)
  ├── Анализирует задачу
  ├── Выбирает уровень сложности
  └── Выбирает модель из пула
       │
       ▼
Hermes встроенный роутер
  ├── Отправляет запрос выбранной модели
  ├── Если провайдер недоступен → переключается на резервного
  └── Если провайдер вернул ошибку → переключается на следующего в цепочке
       │
       ▼
Ответ возвращается пользователю
```

### 4.2. Пошаговая настройка

**Шаг 1. Установите плагин Jev Router (если используете постоянную конфигурацию).**

```bash
hermes plugins install https://github.com/HinkoK/hermes-jev-router
hermes plugins enable jev-router
```

Добавьте ключ в `~/.hermes/.env`:
```
OPENROUTER_API_KEY=ваш_ключ
```
Ключ используется и для Jev, и для выбранных моделей — отдельный ключ TypeSafe не требуется.

**Шаг 2. Настройте пул моделей.**

Создайте `~/.hermes/jev/routing.json` с тремя уровнями (simple / medium / hard) и укажите модели для каждого уровня. Используйте `jev models suggest --write` как отправную точку, затем отредактируйте вручную.

**Шаг 3. Настройте fallback-провайдеров в `config.yaml`.**

```yaml
# ~/.hermes/config.yaml
model:
  provider: openrouter
  model: typesafe/jev-router

fallback_providers:
  - provider: openrouter
    model: openai/gpt-6-sol
  - provider: anthropic
    model: claude-sonnet-4
```

Это гарантирует, что при сбое OpenRouter Hermes переключится на Anthropic, а сессия не прервётся.

**Шаг 4. Включите Jev Router в чате.**

В интерфейсе Hermes (Telegram, Desktop, терминал) отправьте:
```
/router on
```

Jev начнёт выбирать модель для каждого сообщения. Под каждым ответом появится строка вида: «Ответила: GPT-6 Luna · Джев: лёгкое задание · 312 мс».

### 4.3. Что вы получаете в итоге

| Слой | Задача | Что решает |
| :--- | :--- | :--- |
| **Jev Router** | Экономия | Выбирает модель под задачу, избегает переплаты за дорогие модели |
| **Встроенный роутер Hermes** | Надёжность | Переключает провайдеров при сбоях, ротирует ключи, сохраняет сессию |

### 4.4. Рекомендации по запуску

1. **Начните с Shadow Mode.** Перед полноценным включением используйте `/jev routing shadow` в течение дня, чтобы увидеть, какие модели Jev выбирает, не применяя их фактически.
2. **Установите консервативные пороги.** Начните с confidence >= 0.75 и margin >= 0.15, чтобы Jev не принимал решения при низкой уверенности.
3. **Следите за расходами.** Периодически проверяйте `usage.cost` в ответах OpenRouter и сверяйте с ожиданиями. При необходимости сужайте пул моделей через `routing.json`.
4. **Держите fallback-цепочку короткой.** 2–3 провайдера достаточно. Слишком длинная цепочка увеличивает задержку при сбоях.


## 5. Итог

- **Стоимость** при 6 часах активной работы в день: **~$22–$25 в месяц** (при указанных допущениях о распределении задач и среднем размере запроса). Решения Jev стоят **меньше $1 в месяц** — это пренебрежимо малая часть расходов.
- **Встроенный роутер Hermes** — это фундамент надёжности: fallback-провайдеры, пулы ключей, единая точка вызова LLM.
- **Jev Router** — это надстройка для экономии: выбор модели под сложность задачи с точностью 95.8–97.5%.
- **Оптимальное совмещение**: Jev Router как основная модель (`typesafe/jev-router`) + fallback-цепочка провайдеров в `config.yaml` для отказоустойчивости.
