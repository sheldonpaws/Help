Как оказалось в процессе работы с hermes, ему трудно работать с Google AI Studio из за минутных лимитов. Как уже было упомянуто этот агент отправляет в модель несколько фоновых запросов и чем пользовательский запрос сложнее, тем больше он отправляет. я предлагаю установить Omniroute.

Создайте tmux сессию:
Добавьте своего пользователя в группу docker
sudo usermod -aG docker имя_пользователя
Введите пароль пользователя

Обновите сессию группы
newgrp docker

Установите контейнер с omniroute
(замените ВАШ_ПАРОЛЬ):

docker run -d --name omniroute --restart unless-stopped \
-p 8000:20128 \
-v omniroute-data:/app/data \
-e INITIAL_PASSWORD=ВАШ_ПАРОЛЬ \
diegosouzapw/omniroute:latest

Откройте в локальном браузере:
http://IP_ВАШЕГО_UBUNTU_СЕРВЕРА:8000/ и вставьте пароль,который задали для контейнера.

Там во вкладке OMNIPROXY раздела Главная выберите Провайдеры.
Нажмите на вкладку "Уровень бесплатного пользования" и выберите провайдеров
там нужно нажать "Добавить соединение", ввести "hermes" в поле имя, API ключ, взятый у провайдера, выставить приоритет, включить тумблер "Импортировать только бесплатные модели" и нажать "Сохранить".

ВАЖНО!!! Все регистрации, входы и взятия ключей делайте через Docker-браузер

Перейдите в "Менеджер API
Сделайте там API-ключ.

В агенте ведите hermes model, выберите custom (direct API)
Скопируйте публичный эндпоинт из раздела Конечные точки веб-интерфейса omniroute, вставьте в агента, вставьте API-ключ omniroute, нажать 1. Далее я выберу 2 auto best reasoning длина контекста оставлю авто и нажму Enter, отображаемое имя - это имя, которое будет отображаться в списке провайдеров.

Как обещается, при достижении лимитов система бесшовно переключит на другого провайдера. Поэтому надо выбирать авто. 

Если что пойдёт не так
Остановите и удалите контейнер:
docker rm -f omniroute
Удалите старый том с данными:
docker volume rm omniroute-data

Локальные модели:
Deepseek мне посоветовал установить на VPS 8 GB ОЗУ ещё файл подкачки на 8
Делать это нужно из под root, в kitty
sudo fallocate -l 8G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

Если это не сработает (у меня ввбило No such file or directory)
sudo dd if=/dev/zero of=/swapfile bs=1M count=8192 status=progress
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

И проверьте
swapon --show
free -h
Вы должны увидеть /swapfile в списке активных swap-пространств и общий объем swap 8 ГБ.

Верните на пользовательский профиль в прграмме.
Установите на сервер.
curl -fsSL https://lmstudio.ai/install.sh | bash
Запустите процесс.
lms daemon up
Найдите модель в каталоге
https://lmstudio.ai/models
На сервере
lms get название_модели
Запустите  API-сервер
lms server start --port 1234 --bind 127.0.0.1
Проверить
# 1. Проверить статус
lms status

# 2. Проверить, слушает ли сервер порт 1234
curl http://127.0.0.1:1234/v1/models
Если curl выдал список моделей (JSON) — значит, сервер работает (ине он выдал список загруженных моделей).
