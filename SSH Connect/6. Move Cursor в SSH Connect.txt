Move Cursor в SSH Connect
=========================

Прокрутка истории tmux клавиатурой
==================================

По умолчанию tmux хранит историю каждой панели (до 2000 строк, в примере ниже — 50000), но KiTTY не умеет её прокручивать — окно терминала одноразовое, сверх-истории нет. SSH-Connect решает это автоматически через встроенный хелпер Move Cursor: он перехватывает Page Up / Page Down на уровне Windows (низкоуровневый хук WH_KEYBOARD_LL, без внешних библиотек) и вместо голой клавиши отправляет в KiTTY события колеса мыши, которые tmux понимает и листает свою историю. Сама клавиша PgUp/PgDn при этом глотается — KiTTY и tmux её не видят, поэтому листает только tmux, ровно на то число насечек, что задано в конфиге.


Настройка на сервере (один раз)
==============================

SSH-Connect подключается и автоматически запускает Move Cursor на стороне клиента. Но сервер нужно настроить: добавьте в ~/.tmux.conf:

    set -g mouse on
    set -g history-limit 50000


Использование
=============

1. Подключитесь к серверу через SSH-Connect (кнопка "Подключиться")

2. Откройте или создайте tmux-сессию:

3. Нажимайте Page Up / Page Down — tmux покажет историю.
   На одно нажатие уходит столько насечек колеса, сколько задано
   параметром notches в конфиге (1 насечка ≈ 5 строк истории).

4. Shift + Page Up / Page Down — горизонтальная прокрутка
   (если включена параметром horizontal в конфиге move_cursor).

5. F12 — временная пауза перехвата (можно сменить параметром pause_key).
   При паузе PgUp/PgDn снова уходят в KiTTY как обычные клавиши.


Настройки клиента (move_cursor.json)
====================================

Файл move_cursor.json создаётся автоматически рядом с move_cursor.py
при первом запуске. Доступные параметры:

    pause_key    — клавиша паузы (умолч. "f12")
    up_key       — прокрутка вверх (умолч. "page_up")
    down_key     — прокрутка вниз (умолч. "page_down")
    notches      — насечек колеса на одно нажатие (умолч. 4, 1 ≈ 5 строк)
    notch_delay  — пауза между насечками, сек (умолч. 0.05)
    horizontal   — включить горизонтальный скролл Shift+PgUp/PgDn (true/false)
    log          — писать журнал в move_cursor.log (true/false)
    title_matches — заголовки окон, где тоже листать (умолч. [] — выключено)
    use_cursor_point — колесо под курсором, а не в центр окна (true/false)
    sendinput_for_title — способ отправки колеса для окон из title_matches

Последние три параметра для обычной работы не нужны: по умолчанию Move Cursor
листает только KiTTY/tmux, а чат веб-дашборда использует свою прокрутку —
см. «11. Прокрутка чата в дашборде.txt».

Все действия и загруженные настройки пишутся в move_cursor.log —
проверить, что конфиг применился, можно по строке из него.
Изменения вступают в силу после переподключения (GUI убивает и
запускает хелпер заново).


Как это устроено
===============

- Хук WH_KEYBOARD_LL ставится чистым ctypes (никакого pynput —
  только Win32 API, работает на 64-бит, типы заданы явно).
- PgUp/PgDn глотаются, только когда активное окно — KiTTY/PuTTY.
  В остальных приложениях клавиши работают как обычно.
- Веб-дашборд (браузер) Move Cursor не трогает: Page Up / Page Down в чате
  дашборда обрабатывает плагин на самой странице — см. «11. Прокрутка чата
  в дашборде.txt».
- Обработчик хука ничего тяжёлого не делает внутри callback: отправка колеса
  уходит в отдельный поток, поэтому даже частые нажатия не срывают хук
  (Windows снимает хук при задержке обработчика ~300 мс).
- События колеса отправляются через PostMessage в центр окна KiTTY —
  срабатывают даже при свёрнутом окне.
- Хелпер запускается GUI-приложением при подключении и убивается при
  отключении/закрытии приложения (_start_move_cursor/_stop_move_cursor
  в src/gui.py, процесс отслеживается в _move_cursor_proc).
- Чтобы остановить хелпер вручную — завершите процесс pythonw.exe
  (move_cursor.py) в диспетчере задач.
