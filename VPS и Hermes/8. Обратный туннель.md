# Обратный доступ (Reverse Access)

Обратный доступ — механизм, который позволяет агенту Hermes на VPS читать и
записывать файлы в папках Windows-компьютера, где запущен SSH-Connect.

## Зачем это нужно

Компьютер пользователя обычно находится **за NAT** (домашний/офисный роутер) —
у сети нет публичного IP, входящие соединения извне невозможны. Поэтому VPS не
может «дотянуться» до папок Windows напрямую. Решение — **обратный (reverse)
туннель**: соединение всегда инициирует Windows-клиент, а сервер VPS лишь
принимает его и выставляет порт на себя.

Итоговая картина:

```
Windows (SSH-Connect)                  VPS (Hermes)
┌────────────────────┐                 ┌─────────────────────────┐
│ HTTP-сервер        │  SSH-соединение  │ 127.0.0.1:17850 <──→   │
│ 127.0.0.1:<лок>    │ ───────────────► │ (обратный форвард)      │
│ папка A ─ /a/      │                 │ curl .../a/file.txt     │
│ папка B ─ /b/      │                 │ Hermes-агент            │
└────────────────────┘                 └─────────────────────────┘
```

## Как это работает

1. Пользователь подключается к VPS в SSH-Connect (кнопка «Подключиться»).
2. Нажимает **«Доступ»** — открывается менеджер папок. Выбирает одну или
   несколько папок с кнопки «Добавить».
3. Приложение поднимает локальный HTTP-файловый сервер на `127.0.0.1`
   (слушает только на Windows, наружу не торчит) и **одним** туннелем
   выставляет его на VPS.
4. На VPS порт становится доступен как **`http://127.0.0.1:17850/`** —
   фиксированный порт `17850` (`ReverseAccess.FIXED_PORT`).
5. Список папок записывается в манифест `~/.hermes/reverse_access.json`
   (см. ниже). Агент Hermes читает этот файл и знает, какие папки
   расшарены и по каким URL.

## Несколько папок на одном порту

В отличие от старых версий, **порт один** (`17850`) — не нужно плодить
отдельные порты на каждую папку (это путает агента). Все выбранные папки
монтируются как **подпути**:

| Windows-папка              | URL на VPS                          |
|----------------------------|--------------------------------------|
| `D:\Projects\SSH_Connect    | `http://127.0.0.1:17850/ssh_connect/`  |
| `C:\Users\Имя\Документы`   | `http://127.0.0.1:17850/dokumenti/`  |

Слаг (`ssh_connect`, `dokumenti`) строится автоматически из имени папки —
кириллица транслитерируется («Мои документы» → `moi-dokumenti`). Если папок
несколько, слаги остаются стабильными: при добавлении или удалении папки URL
уже открытых папок **не меняются**.

Порт на VPS всегда `17850`. Если он уже занят — старт не происходит, ошибка
показывается. Случайный порт не берётся намеренно: иначе URL агента
«плавал» бы и путал его.

## Как пользоваться в интерфейсе

1. **Подключиться** к серверу.
2. Нажать **«Доступ»** (включается только при активном подключении).
3. Выбрать первую папку в диалоге выбора папки — доступ запустится,
   индикатор рядом с кнопкой станет 🟢.
4. Повторное нажатие «Доступ» открывает **менеджер**: можно добавить ещё
   папки («Добавить»), убрать выбранную («Убрать») или остановить доступ
   полностью («Стоп доступ»).
5. Индикатор: **⚪** — выключено, **🟢** — активно.

Доступ автоматически останавливается при отключении от сервера или закрытии
окна приложения.

## Манифест: `~/.hermes/reverse_access.json`

Файл на VPS, который приложение пишет при каждом (пере)запуске доступа:

```json
{
  "D:\\Projects\\SSH_Connect":       "http://127.0.0.1:17850/ssh_connect/"
  "C:\\Users\\Имя\\Документы":     "http://127.0.0.1:17850/dokumenti/"
}
```

Формат: **папка → полный URL** (включая `/slug/`). Пустой `{}` или отсутствие
файла означает, что туннель не запущен.

Агент использует этот файл так:
- по запросу Windows-пути ищет в манифесте запись, чья папка — **префикс**
  искомого пути;
- берёт из записи URL **как есть** (вместе со слагом);
- приклеивает к нему оставшуюся часть пути.


## HTTP API сервера

| Метод  | Путь                       | Описание                              |
|--------|----------------------------|---------------------------------------|
| GET    | `/`                        | Список монтирований (JSON)            |
| GET    | `/slug/`                   | Список каталога (JSON)                |
| GET    | `/slug/file`               | Скачать файл (сырые байты)            |
| PUT    | `/slug/file`               | Записать файл (каталоги создаются)    |
| MKCOL  | `/slug/dir`                | Создать каталог                       |
| DELETE | `/slug/path`               | Удалить файл или каталог              |

Примеры:

```bash
curl http://127.0.0.1:17850/                              # список папок
curl http://127.0.0.1:17850/ssh_connect/                    # список каталога
curl http://127.0.0.1:17850/ssh_connect/reports/a.txt       # прочитать файл
curl -X PUT --data-binary @x.tmp \
     http://127.0.0.1:17850/ssh_connect/new.txt             # записать
curl -X MKCOL http://127.0.0.1:17850/ssh_connect/newdir     # создать каталог
curl -X DELETE http://127.0.0.1:17850/ssh_connect/old.txt   # удалить
```

Листинг возвращает JSON:

```json
{
  "ok": true, "path": "/ssh_connect", "type": "dir",
  "entries": [
    {"name": "reports", "type": "dir",  "size": null, "mtime": 1730000000,
     "url": "/ssh_connect/reports/"},
    {"name": "a.txt",  "type": "file", "size": 154,   "mtime": 1730000002,
     "url": "/ssh_connect/a.txt"}
  ]
}
```

Имена с кириллицей/пробелами отдаются percent-encoded в поле `url` — агент
может использовать их готовыми, либо кодировать сам (`curl -G
--data-urlencode`, `urllib.parse.quote`).

## Интеграция с Hermes

Агент знает о механизме через скил **`reverse-ssh-tunnel`**
(`~/.hermes/skills/devops/reverse-ssh-tunnel/SKILL.md`):

- приложение автоустанавливает скил на VPS при подключении (если его нет);
- веб-чат включает этот скил по умолчанию — пользователю ничего не нужно
  включать вручную.

Скил содержит описание как диагностики туннеля, так и обращения к папкам
Windows (маппинг путей на URL через curl). В скил включена защитная
инструкция: если порт `17850` уже слушается и отвечает 200 — **не трогать
sshd**, туннель работает.

## Безопасность

- Сервер слушает **только `127.0.0.1`** на Windows и только `127.0.0.1` на VPS —
  до туннеля нет доступа из интернета.
- Пути проверяются через `commonpath` — запрос вроде `/slug/../../etc/passwd`
  не проходит (отдаётся 403).
- Пароли и ключи никогда не передаются через URL туннеля.
- Включение обратного доступа не требует правок `/etc/ssh/sshd_config` —
  `AllowTcpForwarding` включён по умолчанию, а разворот форварда делает
  paramiko-клиент сам.
- Keepalive на SSH-транспорте (`set_keepalive`) предотвращает обрыв
  туннеля по таймауту NAT.

## Устранение неполадок

| Симптом                          | Причина/решение                              |
|----------------------------------|----------------------------------------------|
| «Обратный туннель не удался»     | Порт 17850 занят на VPS (например, уже есть  |
| при нажатии «Доступ»             | активный доступ). Остановите старый доступ.  |
| «TCP forwarding request denied»  | Уже запущен другой обратный доступ на этом   |
|                                  | соединении/порту.                            |
| Агент не видит папки             | Проверьте `~/.hermes/reverse_access.json`:   |
|                                  | пустой `{}` = доступ выключен.               |
| Агент ошибся в URL               | Перезапустите доступ в GUI — манифест        |
|                                  | перепишется с актуальными URL со слагами.    |
| Кириллица в имени файла          | Используйте percent-encoding или готовые     |
|                                  | `url` из листингов.                          |

## Где это в коде

- `src/reverse_access.py` — HTTP-сервер + reverse-туннель (`ReverseAccess`,
  `make_slug`, порт `FIXED_PORT = 17850`).
- `src/gui.py` — кнопка «Доступ», индикатор, менеджер папок
  (`_toggle_reverse`, `_manage_reverse_dialog`, `_start_reverse_access`,
  `_stop_reverse_access`, `_sync_reverse_manifest`, `_write_reverse_json`).
- `src/hermes_skills.py` — содержимое скила `reverse-ssh-tunnel`
  и автоустановщик `install_skill_if_missing`.
- `src/ssh.py` — `set_keepalive` для устойчивости туннеля.
