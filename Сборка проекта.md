Можно, конечно, просто собрать портативную версию, сказав агенту написать скрипт для onedir сборки проекта. Запустить скрипт, запаковать получившуюся папку в архив и распространять так. 

Но если хотите, чтобы ваш продукт выглядел более профессионально или сделать релиз на GitHub, воспользуйтесь инструкцией.

# Что такое Inno Setup

Inno Setup — это бесплатная программа с открытым исходным кодом, которая создает единый .exe-файл установщика для вашего приложения. 
Скачивайте и устанавливайте её как обычную программу на свой компьютер.

# Шаг первый

Поставьте галочку (точку) напротив пункта «Create a new script file using the Script Wizard» (Создать новый файл скрипта с помощью мастера скриптов).
Нажмите OK.

Script Wizard (Мастер скриптов) — это пошаговый помощник с графическим интерфейсом. Он сам задаст вам несколько простых вопросов и на их основе сгенерирует готовый .iss-скрипт. Вам не придется писать код вручную.

# Шаг второй

Application name: Название вашего приложения.
Application version: Версия.
Application publisher: Ваше имя или ник на GitHub.
Application website: Ссылка на ваш репозиторий на GitHub.

# Шаг третий

Main executable file: Здесь нужно бдет указать путь к вашему .exe файлу внутри папки собранной папки (dist). Нажмите «Browse» и выберите его.
Other application files: Мастер спросит, нужно ли добавить другие файлы. Обязательно согласитесь (выберите «Add folder») и укажите путь к вашей папке dist/проект. Это критически важно, чтобы все папки и файлы попали в установщик.

# Шаг четвёртый

На скриншоте всё настроено абсолютно правильно. Можете смело нажимать Next.
Application destination base folder (Базовая папка назначения): Program Files directory. Это стандартное расположение для установленных программ в Windows (обычно C:\Program Files). Оставляем так.
Application folder name (Имя папки приложения): SSH Connect. Установщик создаст внутри Program Files папку с этим названием. Всё верно.
Allow user to change the application folder (Разрешить пользователю менять папку): Галочка стоит. Это хорошая практика — если у пользователя нет прав на запись в Program Files или он хочет поставить программу на диск D, он сможет это сделать.
The application doesn't need a folder (Приложению не нужна папка): Галочка не стоит, и это правильно. Так как у вас в dist есть папки с зависимостями, приложению обязательно нужна своя директория.

# Шаг пятый

Should files in subfolders of
Нажимайте смело «Да».
Это как раз тот самый ключевой момент, о котором мы говорили. Программа спрашивает: «Нужно ли включить в установщик файлы, которые лежат внутри вложенных папок?».
Вам нужно ответить «Да», потому что:
В этих 6 папках лежат библиотеки и ресурсы, без которых ваш .exe не запустится на чужом компьютере.
Если нажать «Нет», Inno Setup упакует только файлы из корня папки, проигнорирует все подпапки, и установленная программа упадёт с ошибкой при запуске.
Сейчас вы выбрали папку dist\SSH-Connect, и этот вопрос означает, что мастер хочет рекурсивно (со всеми вложенными папками) добавить всё её содержимое. Это именно то, что нам нужно.

# Шаг шестой

Здесь лучше снять галочку с пункта «Associate a file type to the main executable» (Связать тип файла с главным исполняемым файлом) и нажать Next.

Почему?
Этот шаг нужен для того, чтобы Windows автоматически открывала вашу программу, если пользователь дважды кликнет по файлу с определенным расширением. Например, как .docx открывается в Word.

.myp — это просто заготовка: Это расширение-пример, которое мастер подставил по умолчанию. Скорее всего, оно не имеет отношения к вашему SSH-клиенту.

Вам это, вероятно, не нужно: SSH-клиенты обычно не открывают файлы двойным кликом. Они подключаются к серверам. Если у вас нет специального формата файлов (например, сохраненные профили подключений с расширением .sshconnect), которые программа умеет открывать через аргументы командной строки, то эта ассоциация только навредит.

# Шаг седьмой

На этом шаге всё настроено почти идеально. Есть только один момент, который стоит поправить для аккуратности.

Create a Start Menu shortcut but no folder (Создать ярлык в меню «Пуск», но без папки):

Рекомендую снять эту галочку. Сейчас у вас стоит галочка, значит ярлык просто свалится в самый корень меню «Пуск». Чтобы не мусорить там, лучше снять галочку — тогда Inno Setup создаст отдельную папку «SSH Connect» в меню «Пуск», и уже внутри неё будет ярлык. Поле Application Start Menu folder name (SSH Connect) как раз для этого и нужно.

Allow user to change the Start Menu folder name: Оставьте галочку. Это даст пользователю возможность переименовать папку в меню «Пуск», если он захочет.

Allow user to disable Start Menu folder creation: Оставьте пустым. Не нужно давать пользователю возможность вообще удалять ярлык из меню «Пуск».

Create an Internet shortcut...: Оставьте пустым. Вашему SSH-клиенту не нужен ярлык на сайт в меню «Пуск».

Create an Uninstall shortcut...: Оставьте пустым. Удаление программ в Windows происходит через «Панель управления» -> «Установка и удаление программ» (или «Приложения» в Windows 10/11). Дублировать деинсталлятор в меню «Пуск» не нужно.

Allow user to create a desktop shortcut (Разрешить создать ярлык на рабочем столе): Оставьте галочку. Это стандартная и удобная опция, почти все пользователи ставят галочку при установке

# Шаг восьмой

Этот шаг полностью опционален. Давайте разберем, для чего они нужны:

License file (Файл лицензии): Сюда можно подгрузить текстовый файл (например, .txt или .rtf) с лицензионным соглашением. При установке пользователю покажется окно, где нужно будет принять условия.

Совет: Если у вас на GitHub в репозитории есть файл LICENSE (например, MIT, GPL, Apache), и вы хотите, чтобы пользователь с ним ознакомился при установке, нажмите Browse... и выберите этот файл. Если лицензии нет или вы не хотите её показывать — оставьте поле пустым.

Information file shown before installation (Информация до установки): Сюда можно загрузить readme.txt с важными предупреждениями (например, «Перед установкой закройте все программы»).

Совет: Обычно оставляют пустым. Современные пользователи редко читают эти экраны.

Information file shown after installation (Информация после установки): Сюда можно загрузить файл с благодарностями или инструкцией по первому запуску.

Совет: Тоже обычно оставляют пустым

# Шаг девятый

Здесь всё настроено верно, оставьте выбранным Administrative install mode (install for all users) и нажимайте Next.

Давайте разбереу, что означают эти режимы, чтобы вы понимали, что происходит:

Administrative install mode (выбрано сейчас):

Программа установится в C:\Program Files для всех пользователей компьютера.

При запуске установщика Windows попросит права администратора (появится окно UAC с вопросом «Разрешить этому приложению вносить изменения...»).

Это стандартный и самый ожидаемый вариант для обычных десктопных программ. Пользователи привыкли к нему. Выбираем его.

Non administrative install mode:

Программа установится только для текущего пользователя в скрытую папку AppData.

Права администратора не нужны.

Этот вариант хорош, если у пользователя нет прав администратора на компьютере (например, на рабочем ПК с жесткими ограничениями). Но для обычного распространения это менее удобно.

Две нижние галочки (Allow user to override... и Ask the user to choose...):

Оставьте их пустыми. Не нужно давать пользователю возможность менять режим установки через командную строку или выбирать его при старте. Это только усложнит процесс и может запутать.

# Шаг десятый

Здесь всё настроено правильно, ничего менять не нужно. Просто нажмите Next.

Давайте кратко разберем, что означают эти пункты, чтобы у вас не осталось сомнений:

Windows registry file (.reg) to import (Файл реестра для импорта):

Оставьте пустым. Вашей программе, скорее всего, не нужно прописывать какие-то специальные настройки в реестр Windows при установке. Эта опция нужна для очень специфических программ (например, драйверов или системных утилит).

Settings (for all keys and values) (Настройки для всех ключей и значений):

Delete keys which are empty on uninstall (Удалять пустые ключи при удалении): Галочка стоит. Это хорошо. При удалении программы установщик почистит за собой пустые папки в реестре.

Also delete keys which are not empty (Также удалять непустые ключи): Галочка не стоит, и это правильно. Если бы вы её поставили, при удалении программы могли бы стереться настройки других программ или общие системные ключи. Оставляем как есть.

Delete values on uninstall (Удалять значения при удалении): Галочка стоит. Это стандартная практика — удалять свои параметры из реестра при деинсталляции.

Minimum Windows version (Минимальная версия Windows):

Оставьте пустым. Если не отметить эту галочку, установщик позволит установить программу на любую версию Windows. Если вы точно знаете, что ваша программа требует, например, только Windows 10 или 11, можно поставить галочку и выбрать версию. Но для обычного SSH-клиента лучше не ограничивать пользователей.

# Шаг одиннадцатый

На этом экране есть пара моментов, которые стоит подправить для удобства и профессионального вида, прежде чем нажимать Next.

Compiler output base file name (Имя выходного файла):

Сейчас стоит mysetup. В итоге у вас получится файл mysetup.exe.

Рекомендую изменить это на что-то понятное, например: SSH-Connect-Setup или SSH-Connect-v1.0.0-Setup. Именно этот файл увидят пользователи, когда скачают его с GitHub или Komi Store. Согласитесь, SSH-Connect-Setup.exe выглядит гораздо лучше, чем mysetup.exe

Custom Setup icon file (Иконка установщика):

Настоятельно рекомендую добавить иконку. Если оставить поле пустым, ваш setup.exe будет выглядеть как стандартный серый значок Inno Setup. Это выглядит непрофессионально.

Нажмите Browse... и выберите файл иконки вашего проекта (формат .ico). Если у вас есть только .png или .exe, из которого можно вытащить иконку, её нужно сначала конвертировать в .ico (например, через онлайн-конвертеры). Если иконки нет вообще, можете пока оставить пустым, но лучше её сделать.

Setup password (Пароль установки):

Оставьте пустым. Ваш проект open-source и бесплатный. Если вы поставите пароль, пользователи не смогут просто так установить программу. Это лишнее.

Custom compiler output folder (Папка сохранения):

Оставьте пустым. По умолчанию Inno Setup создаст папку Output рядом с вашим скриптом. Это удобно, вы сразу найдете готовый файл.

# Шаг двенадцтый

Здесь всё верно — галочка «Yes, use #define compiler directives» стоит, и её нужно оставить. Нажимайте Next.

Что это значит и почему это удобно?
Inno Setup Preprocessor (ISPP) — это специальный инструмент, который позволяет использовать переменные (директивы #define) в вашем скрипте.

Простыми словами: вместо того чтобы по всему скрипту вручную менять название программы, версию или путь к файлам, вы выносите их в самое начало скрипта. Это очень пригодится вам в будущем.

# Шаг тринадцатый

Когда вы захотите выпустить новую версию (например, 1.0.1), вам нужно будет изменить цифру только в одной строчке в самом верху скрипта, а не искать её по всему файлу.

Так как галочка стоит, мастер сгенерирует скрипт именно с такими переменными. Это стандартная и правильная практика.

Жмите Next — это был последний шаг мастера, дальше откроется сам скрипт. О спросит скопиллировать ли новый скрипт. Согласитесь и сохраните скрипт.

По умолчанию Inno Setup создаст папку Output рядом с тем местом, где вы сохранили скрипт (скорее всего, в папке вашего проекта). Внутри этой папки будет лежать файл, который вы назвали (например, SSH-Connect-Setup.exe).

Где-то в конце также будет два экрана, на которых предложат сооттветственно выбрать языки инсталятора и его стиль.
